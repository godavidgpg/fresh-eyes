# 상호작용: 해보면서 걸리는 것

3단계(태스크 수행)와 4단계(상태 스트레스)에서 쓴다.

## 1. 두 개의 간극 (Norman 1986)

| 간극 | 사람의 속마음 | 흔한 원인 |
|---|---|---|
| **실행의 간극** | "어떻게 하는 거지?" | 행동이 숨어 있음, 라벨이 모호함, 필요한 단계를 모름 |
| **평가의 간극** | "된 건가?" | 피드백이 없음, 시선 밖에 있음, 결과가 이전 상태와 비슷해 보임 |

망설임 지점마다 어느 간극인지 적는다. 같은 문제처럼 보여도 고치는 법이 다르다. 실행의 간극은 발견 가능성과 라벨을, 평가의 간극은 피드백을 고쳐야 한다.

## 2. 인지적 워크스루를 빠르게 돌리는 법

네 질문(SKILL.md 3단계)이 무겁게 느껴지면 Spencer(2000)의 간소화 버전처럼 두 질문으로 줄인다.
1. 사람이 이 단계에서 **무엇을 해야 하는지 알까?**
2. 해낸 뒤 **올바르게 하고 있다는 걸 알까?**

## 3. 상호작용 법칙과 기준값

| 법칙 | 무엇을 보나 | 기준 |
|---|---|---|
| **Fitts의 법칙** (Fitts 1954) | 자주 쓰는 행동은 크고 가까운가. 위험한 버튼이 주요 버튼 바로 옆에 붙어 있지 않은가 | 터치 타깃 최소 24×24 CSS px (WCAG 2.2 AA 2.5.8), 권장 44×44pt (Apple HIG), 48×48dp (Material) |
| **엄지 영역** (Hoober 2013) | 모바일에서 주요 행동이 한 손 엄지가 닿는 화면 아래쪽에 있는가 | 관찰된 사용자의 약 49%가 한 손으로 폰을 쥐었다 |
| **Hick의 법칙** (Hick 1952, Hyman 1953) | 한 번에 보이는 선택지 수가 많지 않은가 | 선택지가 많으면 묶거나 기본값을 준다 |
| **작업 기억** (Miller 1956, Cowan 2001) | 이전 화면의 정보를 외워야 하지 않는가 | 동시에 붙들 수 있는 덩어리는 약 4개 |
| **인지 부하** (Sweller 1988) | 화면이 과제와 상관없는 정보로 머리를 쓰게 하지 않는가 | 과제와 무관한 장식, 중복 설명 |
| **선택 과부하** (Iyengar & Lepper 2000) | 요금제나 옵션이 너무 많아서 결정을 미루게 하지 않는가 | 추천 표시나 비교 축을 준다 |
| **Tesler의 법칙** | 시스템이 알 수 있는 값을 사람에게 입력시키지 않는가 | 주소 검색, 카드사 자동 인식, 기본값 |
| **응답 시간** (Nielsen 1993) | 0.1초 / 1초 / 10초 기준 | 1초가 넘으면 진행 표시, 10초가 넘으면 진행률과 취소 |
| **Doherty 임계값** (Doherty & Thadani 1982) | 400ms 안에 반응하는가 | 넘으면 낙관적 UI나 스켈레톤을 쓴다 |
| **피크엔드 규칙** (Kahneman et al. 1993) | 가장 힘든 순간과 마지막 순간이 어떤가 | 완료 화면이 성의 있는가. 끝이 에러나 빈 화면이면 전체 기억이 나빠진다 |
| **만족화** (Simon 1956, Krug 2000) | 사람은 최선이 아니라 **처음 본 그럴듯한 것**을 누른다 | 그럴듯하지만 틀린 선택지가 정답보다 먼저 보이지 않는가 |

측정 방법: `perceive.js`의 `smallTargets`로 24px 미만과 44px 미만 타깃을 확인하고, 모바일 스크린샷에서 주요 행동의 세로 위치를 화면 높이에 대한 %로 적는다.

## 4. 폼

- **라벨은 입력칸 위에** 둔다. 위에 붙은 라벨이 시선 이동이 가장 적다 (Penzo 2006의 아이트래킹). 플레이스홀더만 라벨로 쓰면 입력을 시작하는 순간 라벨이 사라진다.
- **인라인 검증**: 입력을 마친 칸에서 바로 오류를 알려주면 성공률과 완료 시간이 좋아진다 (Wroblewski 2009). 단, 입력하는 중에 빨간 오류를 띄우면 방해가 된다.
- **이유 없는 비활성 버튼**: 제출 버튼을 회색으로만 막아 두고 무엇이 부족한지 말하지 않으면 사람은 막힌다. 누르게 두고 빠진 칸을 알려주는 쪽이 낫다.
- **입력 형식 예방**: 전화번호의 하이픈, 날짜 형식을 사람이 맞추게 하지 않는다. 모바일에서는 알맞은 키보드(`inputmode`)를 띄운다.
- **오류 뒤에도 값이 남는가**: 제출에 실패했을 때 입력한 값이 사라지면 Nielsen #9 위반의 심각도가 4에 가깝다.
- **필수와 선택 표시**가 일관적인가.

## 5. 상태 스트레스 체크리스트 (4단계)

| 상태 | 하는 법 | 지적 신호 |
|---|---|---|
| 빈 상태 | 데이터가 0개인 계정이나 필터 | 빈 화면만 있고 다음 할 일 안내가 없음 |
| 로딩 | `browser_network_state_set`(`--caps=network`)으로 느린 망, 또는 응답 직후 바로 스크린샷 | 스피너가 없음, 레이아웃이 튐(CLS), 버튼이 계속 눌림 |
| 에러 | 빈 제출, 잘못된 형식, `browser_route`로 500 응답 흉내 | 원인 불명 메시지, 영문 스택, 입력값 소실 |
| 새로고침 | 같은 URL로 `browser_navigate` | 작성 중인 내용, 필터, 단계 소실 |
| 뒤로 가기 | `browser_navigate_back` | 모달이 닫히지 않고 페이지를 벗어남, 스크롤 위치 소실 |
| 연타 | 제출 버튼을 빠르게 두 번 `browser_click` | 중복 생성, 중복 결제 요청 |
| 극단 콘텐츠 | 40자 한국어 이름, 999,999,999, 이모지, 공백만 | 넘침, 말줄임 없는 잘림, 줄바꿈 깨짐 |
| 키보드 | Tab, Shift+Tab, Enter, Esc를 `browser_press_key`로 | 포커스가 안 보임, 순서가 화면 순서와 다름, 모달 밖으로 포커스가 샘 |
| 확대, 좁은 폭 | `browser_resize` 320×800, 또는 `document.body.style.zoom='2'` | 가로 스크롤, 고정 헤더가 화면 절반을 가림 |
| 다크 모드 | `browser_emulate_media` colorScheme dark | 일부만 색이 바뀜, 흰 배경 이미지가 떠 보임 |
| 동작 줄이기 | `browser_emulate_media` reducedMotion reduce | 큰 애니메이션이 그대로 남음 |
| 콘솔과 네트워크 | `browser_console_messages`, `browser_network_requests` | 에러, 4xx·5xx, 눈에는 안 보이는 실패 |

## 6. 신뢰와 다크 패턴

사람은 속았다고 느끼면 그 서비스를 다시 믿지 않는다. 앱 리뷰에서 별점을 가장 크게 깎는 불만도 프라이버시·윤리 문제와 숨은 비용이었다 (Khalid et al. 2015). 아래 패턴은 발견하면 심각도 3 이상으로 둔다 (Gray et al. 2018, Mathur et al. 2019의 분류).
- **숨은 비용**: 마지막 단계에서야 수수료, 배송비, 자동 결제가 보인다
- **해지 미로**: 가입은 한 번에 되는데 해지는 여러 단계를 거치거나 숨어 있다
- **확인 망신 주기**: "아니요, 저는 할인이 싫어요" 같은 거절 문구
- **미리 체크된 동의**: 마케팅 수신, 유료 옵션이 기본으로 켜져 있다
- **가짜 긴급성**: 근거 없는 카운트다운, "3명이 보고 있어요"
- **잘못 유도하는 위계**: 수락 버튼은 크고 채워져 있는데, 거절은 회색 작은 텍스트다

## 7. 실패를 되돌릴 수 있는가

- 삭제에 확인 단계 또는 **되돌리기**가 있는가. 되돌리기(예: Gmail의 보내기 취소)가 확인 대화상자보다 흐름을 덜 끊는다.
- AI 생성 결과에 수정, 복사, 중단, 이전 버전으로 돌아가기가 있는가. "다시 생성"만 있으면 사람은 마음에 들었던 결과를 잃는다.
- 설정을 바꾼 뒤 기본값으로 되돌리는 길이 있는가.
