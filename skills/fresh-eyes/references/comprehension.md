# 이해: 이름을 모르는 사람은 기능을 어떻게 알아내는가

2단계(이름 모르는 사람 테스트)와 3단계(태스크 수행)에서 쓴다.

## 1. 왜 에이전트는 사람처럼 보지 못하는가

에이전트가 보는 것과 사람이 보는 것은 다르다.

| 에이전트가 아는 것 | 사람이 아는 것 |
|---|---|
| `button "Export to CSV" [ref=e42]` | 오른쪽 위 작은 화살표 아이콘 하나 |
| 링크의 `href`, 이동할 경로 | 파란색인지, 밑줄이 있는지 |
| `disabled` 속성과 그 이유가 적힌 코드 | 회색 버튼. 왜 안 눌리는지는 모름 |
| 컴포넌트 이름 `<UpsellModal>` | 갑자기 뜬 창 |
| 숨겨진 메뉴의 모든 항목 | 햄버거 아이콘 뒤에 뭐가 있는지 모름 |

그래서 이 스킬은 **정보의 순서**를 강제한다. 먼저 스크린샷, 그다음 접근성 트리, 마지막으로 코드 순서다. 순서를 지키지 못했다면 보고서의 "한계"에 적는다.

## 2. 사람은 기능을 이렇게 추측한다

사람이 "이게 뭐 하는 거지?"에 답할 때 쓰는 단서는 순서대로 다음과 같다.

1. **보이는 글자** (라벨, 버튼 텍스트). 가장 강한 단서다.
2. **위치와 관습**. 왼쪽 위 로고는 홈으로, 오른쪽 위는 계정, 아래 탭바는 주요 섹션이다. 사람은 다른 사이트에서 배운 대로 기대한다 (Jakob의 법칙).
3. **아이콘의 모양**. 라벨 없이 의미가 통하는 아이콘은 드물다. 돋보기(검색), 집(홈), X(닫기), 휴지통(삭제) 정도이고, 햄버거 메뉴조차 모두가 아는 것은 아니다 (NN/g, 아이콘 사용성 연구).
4. **주변 맥락**. 카드 안의 하트는 저장일 것 같고, 입력칸 옆의 눈 아이콘은 비밀번호 보기일 것 같다.
5. **시그니파이어**(눌릴 수 있다는 신호). 채워진 배경, 테두리, 밑줄, 그림자, 커서 변화가 여기에 해당한다 (Norman 2013). 신호가 약한 플랫 디자인은 사람을 느리게 만든다. NN/g의 아이트래킹 연구(Moran 2017)에서 시그니파이어가 약한 페이지는 같은 페이지의 강한 버전보다 탐색 시간이 평균 22% 길었다.

아이콘에 대한 연구 결론은 일관된다. 아이콘은 **라벨과 함께 있을 때** 가장 빠르고 정확하게 이해된다 (Wiedenbeck 1999). 아이콘 이해도는 구체성(실물을 닮았는가)과 친숙도에 크게 좌우된다 (McDougall, Curry & de Bruijn 1999). 라벨은 hover할 때가 아니라 **항상 보여야** 한다 (NN/g).

## 3. Blind Control Reading 절차

### 3-1. 픽셀만 보고 목록 만들기

스크린샷에서 다음 요소를 모두 찾는다.
- 눌릴 것 같은 모든 것 (버튼, 링크, 아이콘, 카드, 탭, 토글)
- 눌릴지 안 눌릴지 애매한 것 (색 있는 텍스트, 배지, 칩, 이미지)
- 라벨 없는 아이콘 전부

표로 적는다.

| # | 보이는 모습 (위치, 모양, 글자) | 추측 기능 | 확신 | 눌릴 것 같나 | 누를 용기 |
|---|---|---|---|---|---|
| 1 | 오른쪽 위, 박스에서 위로 나가는 화살표, 라벨 없음 | 공유? 내보내기? | 낮음 | 예 | 중간 |
| 2 | 카드 아래 회색 "자세히" | 상세 페이지로 이동 | 중간 | 애매 | 높음 |

**누를 용기**는 실제로 중요한 지표다. 되돌릴 수 있을지 모르는 버튼, 결제나 삭제처럼 보이는 버튼은 확신이 낮을 때 사람이 아예 누르지 않는다. 그러면 기능이 있어도 쓰이지 않는다.

### 3-2. 정답 확인

1. `perceive.js`의 `controls`를 읽는다. 각 요소의 `text`(보이는 글자), `name`(접근성 이름), `iconOnly`, `signifier`(강함 / 약함 / 없음), `fakeButton`(커서는 손가락인데 키보드로 접근 불가)이 나온다.
2. `browser_snapshot`으로 역할과 이름을 확인한다.
3. 확신이 낮거나 중간인 요소 중 **부작용이 없는 것**을 실제로 누르고, 결과를 스크린샷으로 남긴다. 사람의 1차 추측이 맞았는지 본다.

### 3-3. 어긋남 판정

SKILL.md 2단계의 다섯 유형(의미 불일치, 숨은 어포던스, 거짓 어포던스, 이름 불일치, 정보 냄새 부족)으로 분류한다. 심각도는 다음을 기준으로 잡는다.
- 핵심 태스크에 필요한 요소에서 의미 불일치나 숨은 어포던스가 있으면 **3 이상**이다
- 되돌릴 수 없는 동작(삭제, 결제, 발송)을 다른 것으로 오해할 수 있으면 **4**다
- 보조 기능의 아이콘이 애매하면 **2**다

## 4. 정보 냄새 (Information Scent)

사람은 정보를 찾을 때 동물이 먹이 냄새를 따라가듯 **라벨이 풍기는 단서**를 따라간다 (Pirolli & Card 1999, 정보 섭식 이론). 냄새가 약하면 사람은 되돌아가거나 포기한다.

**냄새가 약한 라벨**: 더보기, 바로가기, 클릭하세요, 자세히, 시작하기(무엇을?), 확인(무엇을 확인?), 회사 내부 용어나 기능 코드명

**냄새가 강한 라벨**: 무엇을 얻는지와 어디로 가는지가 들어 있는 라벨. "요금제 비교하기", "3월 거래내역 보기", "100원 송금하고 계좌 인증하기"

**버튼 라벨 점검법 (대화 테스트)**: 버튼 라벨이 "이 버튼을 누르면 ____" 문장의 빈칸에 자연스럽게 들어가는가? 확인 대화상자의 버튼은 질문에 대한 대답이 되는가? "정말 삭제할까요?"에는 "확인 / 취소"보다 "삭제 / 취소"가 맞는 답이다.

## 5. 멘탈 모델과 용어

- **사용자의 말을 쓰는가**: 화면의 단어를 페르소나가 소리 내어 말하는 단어로 바꿔본다. 개발자 용어(동기화, 인스턴스, 워크스페이스, 토큰), 영문 에러, `null`, `undefined`, 내부 ID가 보이면 Nielsen #2 위반이다.
- **같은 것은 같은 이름으로**: 한 화면에서는 "프로젝트", 다른 화면에서는 "워크스페이스"라고 부르면 사람은 둘이 다른 것이라고 생각한다.
- **트렁크 테스트** (Krug 2000): 아무 하위 페이지에 갑자기 떨어졌을 때 답할 수 있는가? 여기는 어떤 사이트인가, 지금 어느 페이지인가, 주요 섹션은 무엇인가, 지금 어디쯤에 있나, 검색은 어디서 하나.

## 6. UX 문구 점검

보이는 글자는 사람이 기능을 이해하는 가장 강한 단서이므로 문구도 이해의 문제로 본다.
- **잡초 뽑기**: 빼도 뜻이 통하는 단어는 뺀다 (토스 라이팅 원칙의 한 항목). "~를 진행하실 수 있습니다"는 "~할 수 있어요"로 줄인다.
- **한 화면, 한 메시지**: 두 가지를 한 문장에 묶지 않는다.
- **에러는 원인과 해결책을 함께 말한다**: "오류가 발생했습니다"가 아니라 "카드 유효기간이 지났어요. 다른 카드를 등록해 주세요"처럼 쓴다.
- **어조가 일관적인가**: 해요체와 합니다체가 섞여 있지 않은가.
- **unslop 신호**: 느낌표, 인사말 헤드라인("다시 오신 걸 환영해요! 👋"), 과장어(혁신적인, 손쉽게, 마법 같은), 확인할 수 없는 주장("10,000+ 팀이 사랑하는")이 있는가. 이런 문구는 [visual-craft.md](visual-craft.md)의 AI 티 신호에도 해당한다.

## 7. Fresh eyes 서브에이전트 프롬프트 틀

Agent 도구가 있으면 코드 맥락이 없는 서브에이전트에게 아래 내용을 그대로 넘긴다. **코드, 컴포넌트 이름, URL 경로, 이 대화의 맥락은 넘기지 않는다.** 스크린샷 파일 경로, 페르소나, 목표만 넘긴다.

```
너는 이 서비스를 처음 보는 사람이다. 페르소나: <예: 스마트폰은 매일 쓰지만 이 서비스는 처음인 52세 자영업자>.
목표: <예: 지난달 매출을 확인하고 싶다>.

아래 스크린샷 파일들을 Read로 열어서 이미지만 보고 답해라. 다른 파일이나 코드는 열지 마라.
- <절대경로>/qa/home-390-default.png
- <절대경로>/qa/home-390-squint.png

1. 5초 동안 봤다고 치고: 이건 무슨 서비스인가? 첫인상 형용사 3개는?
2. 눈이 가는 순서대로 다섯 개를 적어라.
3. 눌릴 것 같은 요소마다 표로 적어라: 보이는 모습 / 무슨 기능 같은지 / 확신(높음·중간·낮음) / 누를 용기.
4. 목표를 이루려면 가장 먼저 어디를 누르겠나? 왜? 망설여지는 점은?
5. 이 서비스 앱스토어 리뷰에 한 줄 남긴다면?
추측은 추측이라고 써라. 모르는 건 모른다고 써라.
```

결과를 받으면 내 Blind 표와 나란히 놓는다. **두 판단이 모두 틀린 요소**가 가장 확실한 결함이다. 한쪽만 틀렸다면 둘 다 기록하고 심각도는 한 단계 낮춘다.
