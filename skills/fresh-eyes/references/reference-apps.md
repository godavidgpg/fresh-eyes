# 레퍼런스: 잘 만든 앱은 무엇을 다르게 하는가

7단계(선택)에서 비교 기준을 세울 때 쓴다. **베끼는 목록이 아니다.** 같은 문제를 잘 푼 사례를 옆에 두고 "이 서비스는 무엇이 다르게 느껴지는가"를 말로 짚기 위한 것이다. 각 항목은 공개적으로 널리 알려진 패턴만 적었다. 앱은 계속 바뀌므로, 비교할 때는 현재 화면을 직접 찍어서 확인한다.

## 패턴별 레퍼런스

| 평가 대상 | 레퍼런스 | 무엇을 보고 배우나 |
|---|---|---|
| 송금, 금융, 복잡한 절차 | **Toss** | 한 화면에 한 질문만 묻는 단계형 흐름. 큰 숫자 키패드. 모든 문구를 해요체로 통일하고 쓸모없는 단어를 빼는 라이팅 원칙("잡초 뽑기"). 금융 용어를 일상어로 바꾸는 태도. 단, 친근한 용어가 위험을 가린다는 비판도 받았으니 위험한 상품에서는 쉬운 말과 정확한 말의 균형을 본다 |
| 결제 폼, 입력 검증 | **Stripe Checkout** | 카드 번호를 입력하면 카드사를 자동으로 인식한다. 형식은 자동으로 맞춰 주고, 오류는 칸 바로 아래에 사람 말로 보여준다. 필수 칸이 적다 |
| 생산성 툴, 키보드 흐름 | **Linear** | 명령 팔레트(⌘K)와 단축키로 모든 행동에 접근한다. 낙관적 UI로 즉시 반응하는 체감 속도. 크롬은 조용하고 상태 색만 의미를 가진다 |
| 빈 상태, 점진적 공개 | **Notion** | 빈 페이지에서 `/` 하나로 모든 블록을 부른다. 처음에는 단순하게 보이고 필요할 때 기능이 드러난다 |
| 온보딩, 가입 전환 | **Duolingo** | 가입보다 첫 레슨을 먼저 하게 한다(점진적 참여). 진행 상황과 보상을 즉시 보여주고, 레슨 끝을 축하로 마무리해 피크엔드를 설계한다 |
| 검색 중심 서비스, 가격 투명성 | **Airbnb** | 검색창이 화면의 주인공이다. 사진이 먼저 보인다. 수수료를 포함한 총액 표시 옵션으로 마지막 단계의 가격 충격을 줄였다 |
| 실수 복구 | **Gmail** | 보내기 취소. 확인 대화상자로 흐름을 끊는 대신 되돌릴 시간을 준다 |
| 모바일 플랫폼 관습 | **iOS 기본 앱 (Apple HIG)** | 44pt 타깃, 큰 제목에서 작은 제목으로 바뀌는 내비게이션, 시스템 관습을 따라서 새로 배울 게 없음 |
| 협업 툴의 현재 상태 | **Figma** | 누가 어디를 보고 있는지 커서와 아바타로 보여준다. 선택한 대상에 맞춰 바뀌는 속성 패널 |
| 브랜드 정체성 | **배달의민족** | 전용 서체와 말투가 화면 어디서나 제품을 알아보게 만든다. 정체성은 장식이 아니라 타입과 문구에서 나온다 |
| 조용한 다크 UI, 개발자 도구 | **Vercel, Raycast** | 중립색 단계와 머리카락 선만으로 깊이를 만든다. 강조색이 거의 없어서 상태 표시가 바로 읽힌다 |

## 비교하는 법

1. 평가 대상 화면과 같은 역할의 화면을 레퍼런스에서 고른다 (예: 우리 가입 폼 ↔ Stripe Checkout 결제 폼).
2. 공개된 페이지면 같은 뷰포트로 찍는다. 로그인이 필요하면 공식 디자인 블로그, 가이드, 스토어 스크린샷을 쓰고 출처를 적는다.
3. 세 가지만 비교한다. 첫 눈에 주인공이 무엇인가 / 핵심 행동까지 몇 단계인가 / 실패했을 때 무엇을 보여주는가.
4. 보고서에는 "Stripe처럼 바꿔라"가 아니라 "Stripe는 카드사를 자동 인식해 입력 칸 1개를 없앴다. 우리 폼은 카드사를 직접 고르게 한다(Tesler의 법칙)"처럼 **원리와 함께** 쓴다.
